# O-RAN policies and measured outcomes: companion artifact

Companion material for **From O-RAN Policies to Measured Outcomes: Release and Recovery in Practice**.

- Read the [technical supplement PDF](technical_supplement.pdf): complete methods, Tables S1-S19, and Figures S1-S2.
- Download [companion_sources.zip](companion_sources.zip): editable TeX sources, selected retained data, portable analysis code, file manifest, and third-party license text.
- Read [REPRODUCIBILITY.md](REPRODUCIBILITY.md) for the exact numerical reproduction limits.
- Check [CHECKSUMS.txt](CHECKSUMS.txt) to verify the downloaded ZIP and PDF.

## Download, extract and build

Download `companion_sources.zip` and extract it into a new folder. Open a terminal **inside the extracted folder**, where `build_supplement.py` is located.

Requirements: Python 3 and TeX with `latexmk`/`pdflatex` plus the standard packages listed in `reader_preamble.tex`. The Python tools use only the standard library.

```text
python -B build_supplement.py --compile
```

This rebuilds the complete supplement without starting any radio service. The extracted `README.md`, `DATA_INDEX.md`, `PACKAGE_FILES.txt` and `ARTIFACT_MANIFEST.json` describe and identify the files within the ZIP. Their relative file links refer to the extracted folder, not to this repository's top level.

## Recompute the retrospective analysis

From the extracted folder, choose an output directory that does not already exist:

```text
python -B posthoc/analyze_points_5_6.py --output results_recomputed
```

The script verifies all 48 original action outcomes from 1,067 normalized reports in 12 instrumented episodes, then reproduces Table S18 and the crossing-batch diagnostic. The added 60% low-threshold endpoint is **post-hoc shadow analysis**; no actual restoration proposal or E2 command was generated by that analysis.

## Scope of this release

This is a document and selected-analysis artifact, not the complete radio platform or all raw experiment captures. It can rebuild all 19 displayed tables and two figures as a document. It can also rerun the included source-provenance and retrospective analysis from normalized observations. It does **not** reproduce every table from raw inputs.

The ZIP retains 720 delivery-timing rule-pair outcomes, 90 aggregate groups and pending-restoration counts; those are outputs from separate campaigns, whose raw inputs are not all included. See [REPRODUCIBILITY.md](REPRODUCIBILITY.md) for table-by-table coverage. Raw-reference fields and project-relative `revision/...` references identify retained source records, not files necessarily distributed here.

The software-radio campaigns use one host, one UE and a software-radio path. They do not establish field reliability, a universal source-lag bound, or a benefit unique to a record representation.

No blanket license is assigned to the author manuscript, figures, data or code. The included OCUDU source retains its own copyright and license; see [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). This repository does not claim publisher or upstream-project endorsement.

The supplied PDF contains 27 pages. It includes Tables S1-S19 and Figures S1-S2.

Section 11 and Table S19 report a single-host concurrency test. The included retained data and code are described in `concurrency/README.md` inside the extracted archive. These measurements do not establish RAN control-path capacity or deployment-scale reliability.

The selected parameter extract `data/kpm_period_fields.csv` retains decoded granularity fields for 1,067 reports. `data/implementation_parameter_manifest.json` records requested settings, source hashes and implementation-audit locations. These files support reaggregation of the 891/176 report counts; they do not replace the separately retained raw captures.

The selected model and replay evidence includes `data/natural_clearance_audit.json`, `data/lifecycle_scenarios.csv`, `data/lifecycle_scenario_summary.json`, and `data/tractor_source_timing.csv`. They expose modeled natural-clearance counts, ten specified software-only schema/identifier checks, and source-stream timestamp gaps. The summary JSON selects two 10/10 metrics with a source hash; the other three files are byte-identical retained results. These checks are separate from the live E2 cycles and do not establish field reliability or uninterrupted periodic delivery.

Section 10.1 distinguishes the nominal measurement period from host monotonic elapsed time. Its retained byte counts and rates are unchanged. A virtual-radio/host time difference is a possible explanation in the ZeroMQ setup, not an established cause or a measured KPM bias. Reset and snapshot traces do not retain slot identifiers.
